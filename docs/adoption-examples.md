# Choosing skills for a project

Install selected skill directories or the complete collection. Keep real
commands and authority in the adopting repository's instructions. Do not copy
example runtime names or branch choices as universal defaults.

## A library with deterministic tests

Use strix-deliver, strix-plan, strix-implement, and strix-branch-review. Declare
build and focused-test commands, plan location, review-provider permission, and
commit mode in repository instructions. Add strix-autoreview if its runner is
approved. A documentation correction needs focused documentation checks and
resident inspection. A parser behavior change needs regression evidence and
combined closeout review. Neither inherently needs a browser or database.

## A web application with existing development tooling

Add strix-ui, strix-code-impact, and strix-verify-web. Point project instructions
to the actual design system, runtime manager, fixture source, credential owner,
and browser driver. Trace an API change from handler to caller and cache state.
For a responsive menu correction, inspect rendered focus and narrow-layout
behavior after repairs settle. Keep browser artifacts outside runtime cleanup.
Use strix-create-verifier if no source-backed verification recipes exist.

## A protected repository with a release workflow

Add strix-publish-pr, strix-ship, and strix-release. Declare protected checks,
trusted merge and release procedures, artifact identity, and migration recovery.
"Make the PR and babysit it" ends at a mergeable green head. "Ship it" includes
merge. "Check release status" does not dispatch a release. An ambiguous release
response requires read-only run discovery, not another write.

## Concurrent feature work

Add strix-worktree and, for requested terminal retirement, strix-close-worktree.
Declare the existing coordinator or native source-only worktree procedure and
resource ownership. Two features may use separate branches and runtime state.
Do not add a shared mutable journal just to coordinate them. Before removal,
prove the exact disposition and clean state, retain branches, and remove only
owned resources with cleanup authority.

## Review-only use

Install strix-branch-review, strix-bug-hunt, or strix-trim-complexity as needed.
A request for findings only leaves source and Git state unchanged. A combined
bug-hunt-and-branch-review request authorizes localized repairs unless explicitly
read-only; commits still follow project policy. No review request implies a push.
