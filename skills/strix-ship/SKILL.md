# Strix ship

Treat explicit shipping or merge language as authority for publication when
needed, in-scope conflict and CI repairs, and merge of that exact requested set.
PR creation or babysitting alone does not authorize merge. Preserve batch
membership; unrelated queued work does not extend the task.

Read the project's protected Git and merge procedures. Resolve each reviewed
tip, remote head, target, PR, validation, review, and applicable operational
evidence. Publish missing PRs through strix-publish-pr when installed or the
project's procedure. Reuse the same user authority after localized repairs.

Read the complete changed-file manifest, including rename and deletion origins.
Treat missing pages or unknown provider state as incomplete. Apply the project's
migration and trust-boundary rules to the whole set. Before merging dependent
schema changes, inspect the combined migration graph and semantic interactions,
resolve conflicts through authored changes, and renew required safety evidence.
Do not invent a universal migration queue or controller.

Use the configured protected merge route. When trusted automation owns merge,
submit the exact reviewed identity through its supported admission mechanism
and monitor it; do not compete with it or simulate its approval labels. Never
let candidate-modified code establish its own trusted approval. Otherwise use
the host's protected PR merge operation bound to the expected head.

Immediately before merge, confirm the remote head, mergeability, required
checks, and project approvals. A changed head invalidates the affected evidence.
Never bypass protection, force-push, or directly push to the target branch.
Repair in-scope conflicts or CI failures and renew affected checks and review.
Stop for material unresolved decisions, unknown work, or unrecoverable external
failure; preserve completed merges and remaining candidates.

Prove each requested merge through fresh provider and Git evidence. Account
for the project's merge strategy: ancestry for merge commits or accepted
squash-equivalence evidence. Report PR URLs, reviewed heads, merge commits,
resulting target, and any remaining item. Do not deploy, reconcile runtimes,
mutate issues, delete branches, or retire worktrees without separate authority.
